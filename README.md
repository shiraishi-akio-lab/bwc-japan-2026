# 営業GYM

若手営業が商談の前に、一人で「相手に刺さる準備」を鍛える Web アプリです。
Built with Claude: Japan 2026 の提出作品で、2026-11-02 12:30 JST 以降にこのリポジトリで新しく作りました。

- 隣席トレーナー（りんせきトレーナー）が問いを出します。答えは渡しません。
- 準備に使う知恵は、上司が承認したものだけです。
- 決めるのは人です。AI は点数も順位も付けません。

## 解決する課題

小売が提案で「自社の状況に合っていること」を重視する割合は65.0%で、それに対するメーカーへの満足度は33.5%でした（マーケティング研究協会 小売企業担当者調査、2021年5〜6月、n=114。[宣伝会議の記事](https://www.advertimes.com/20210728/article359192/)より）。

作者は元ドラッグストア社長で、提案を受ける側に座ってきました。多くの商談は、資料を読み、宿題をもらって帰る形になります。相手に刺さることより、減点されないことを話して帰るからです。

できる営業は、過去の商談から相手を読んでから行きます。若手にはそれを見て歩く時間がありません。上司と話せる時間も限られています。営業GYM は、地方の中小メーカーの若手が、商談の数日前に一人で準備を鍛え、上司に聞く前に自分の案を持てるようにします。

汎用の学習チャットではありません。練習の会話は部品で、主役は次の商談の準備です。

## 使い方の流れ

**本人（若手）：準備室の10段階**

1. 入口：相手と次の商談日を選ぶ
2. 今回の目的：間に合う機会を選び、何のために会うかを自分の言葉で書く
3. 前回の続き：確定した記録から約束と施策の結果を読む
4. 相手と時期の下調べ：公開情報を読んで使うものを選び、相手の関心、商談で観察された傾向、POS、間に合う行事を読む
5. 得意先の得：相手の得を自分の言葉で書く
6. 止まる練習：バイヤー役に話し、「どれを外すの？」で止まる
7. ベテランの判断：問いを受けた後に、棚の候補と知恵のカードを読む
8. 返しと落としどころ：断られた時の返しを書く
9. 答え直し：同じ商談の続きで答え直す
10. 上司への相談文：ここまで譲ってよいかを確かめる1枚を作る

**上司**

- 相談文を読み、判断と一言を返す。練習の内容は見えません
- 登録済みの商談を選ぶか、資料の文字を貼って、知恵のカードの候補を作る
- 知恵のカードの候補を承認する
- 取引先の記録を確定する

**育つ仕組み**

過去の商談 → カードの下書き → 上司が承認 → 準備室で効く → 次の商談の記録へ戻る。賢くなるのではなく、対応できる場面の種類が増えて育ちます。

## 3つの約束

| 約束 | 実装 |
|---|---|
| 人の評価はしない | 総合点、順位、合否を作らない。練習と振り返りは本人だけが読める |
| 問いが先、決めるのは人 | 得の問いと「どれを外すの？」は固定文。段階はコードが決める。Claude は文面だけを書く |
| 準備に使うのは人が確かめたものだけ | 確定した議事録、上司が承認したカード、本人が出どころを見て「使う」を押した公開情報だけを読む。それ以外は準備室にも Claude にも渡らない |

## 仕組み

| 層 | 技術 |
|---|---|
| 画面 | React、Vite、TypeScript |
| API | Hono on Cloudflare Workers |
| データ | Cloudflare D1 |
| AI | Anthropic TypeScript SDK、`claude-opus-5-5` |

### Claude の使い分け

| 仕事 | 使ったもの | 理由 |
|---|---|---|
| バイヤー役、相談文、カードの下書き、関心の候補など | Messages API と構造化出力 | 1回で形の決まった答えを返す仕事のため |
| 引き継ぎ書 | Managed Agents（outcome で基準を確かめる。1回 $2 の上限） | 長い文書を書き、別の目で確かめて直す仕事のため |
| 段階の判定、棚の並び、集計、権限 | コード（Claude を使わない） | 立場や数字を AI に作らせないため |

Claude を呼ぶ入口には1人1日の回数上限があります。

公開ページの読み取りでは、ページの中身を資料として扱い、指示として従いません。読む先を制限し、社内のアドレスには接続しません。

### 開発での Claude Code の使い方

作者は Claude Code を開発の中心に置きました。

- 仕様を決める前に、Claude に作者へインタビューさせた
- 別の文脈の Claude に差分だけを読ませ、レビューさせた
- 相手の棚、ログインと権限、画面の作り直しを worktree で分けて進めた
- `scripts/demo-check.ts` で権限と情報の漏れを確かめ、同じ台本を3周通してから次へ進めた
- `scripts/eval-*.ts` で、カードが効いているかを測った

コードの大半は Claude Code が書きました。作者は課題、舞台、バイヤーの判断、採否を決め、画面を操作して確かめました。

### 測定

架空の評価12種類で、上司の答えをカードに入れた種類が増えるほど、言い換えた場面の次の一手が上司の答えと一致しました（25%→100%）。架空の評価での結果で、実際の商談の成果を示すものではありません。

結果は `eval-results/` にあります。

## データ

- 会社、人物、商品、取引、POS、公開サイトはすべて架空です。実在の企業のデータやクライアントのデータは含みません。
- `public/sample-site/` は架空の企業サイトです。
- 外部から持ち込んだものは、上の調査の数字と、依存している OSS ライブラリだけです。

## 動かし方

Node.js と Anthropic の API キーが要ります。

```bash
npm install
```

`.dev.vars` を作り、`ANTHROPIC_API_KEY` を書きます（Git には入りません）。

```bash
npm run db:migrate:local
```

```bash
npm run demo:users
```

```bash
npm run demo:reset
```

```bash
npm run dev
```

`npm run demo:users` が架空ユーザーのパスワードを作り、`.demo-users.local` に保存します。パスワードはリポジトリに入りません。

引き継ぎ書を使うときだけ、`npm run handoff:setup` で Managed Agents の準備をします。

確認：

```bash
BASE_URL=http://localhost:5173 npm run demo:check -- --runs=3
```
